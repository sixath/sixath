# Agent 平台需求规格说明书

## 一、工具管理（Tool Management）

### 1.1 添加工具

| 配置项 | 说明 | 必填 |
|--------|------|------|
| 工具名称 | 唯一标识 | 是 |
| 工具描述 | 功能说明 | 是 |
| 工具类型 | 内置工具 / MCP 工具 | 是 |
| 工具配置 | 根据类型不同而不同 | 是 |

**内置工具配置：**

- 函数/方法路径
- 参数 Schema（JSON Schema）
- 调用方式（同步/异步）

**MCP 工具配置：**

- MCP 服务器标识
- 工具名称（对应 MCP 工具）
- 连接配置（URL、认证等）
- 超时设置

### 1.2 工具增删改查（CRUD）

| 功能 | 说明 |
|------|------|
| **创建** | 新增工具，需校验配置完整性 |
| **读取** | 按 ID、名称、类型查询；支持分页、筛选 |
| **更新** | 修改工具配置，更新后需重新校验可用性 |
| **删除** | 删除工具；若已被 Agent 绑定，需提示或级联处理 |

### 1.3 工具类型

| 类型 | 说明 | 特点 |
|------|------|------|
| **内置工具** | 平台预置或用户自定义函数 | 本地执行、低延迟、可离线 |
| **MCP 工具** | 通过 MCP 协议调用的外部工具 | 可扩展、支持远程服务、需网络 |

## 二、Agent 管理（Agent Management）

### 2.1 添加 Agent

| 配置项 | 说明 | 必填 |
|--------|------|------|
| Agent 名称 | 唯一标识 | 是 |
| Agent 描述 | 用途说明 | 否 |
| 系统提示词 | 角色与行为设定 | 否 |
| 模型配置 | 使用的 LLM 及参数 | 是 |
| 默认工具集 | 默认绑定的工具 | 否 |
| Workspace | 工作空间 | 是 |

### 2.2 技能添加

为 Agent 添加技能时，通过上传技能压缩包完成：

| 步骤 | 说明 |
|------|------|
| **上传** | 上传技能压缩包（如 .zip） |
| **校验** | 校验技能包格式、结构、脚本等，校验通过后方可继续 |
| **解压** | 校验通过后，解压到该 Agent 的 `workspace/skills` 目录下 |

**校验项：**

- 压缩包格式合法、可正常解压
- 包含必需的技能定义文件（如 SKILL.md）
- 脚本文件存在性、扩展名符合规范（.sh / .py / .js 等）
- 无路径逃逸风险（如 `../` 等非法路径）

**存储路径：** `{agent_workspace}/skills/`

### 2.3 技能管理

技能不单独建表，通过扫描 Agent 的 `workspace/skills` 目录发现该 Agent 绑定了哪些技能。

| 功能 | 说明 |
|------|------|
| **技能发现** | 扫描 Agent 的 `{workspace}/skills/` 目录，列出该 Agent 下所有技能（每个子目录为一个技能，含 SKILL.md 视为有效） |
| **技能列表** | 在 Agent 详情页展示已绑定的技能列表，展示技能名称、描述等 |
| **技能删除** | 支持删除单个技能，删除时移除 `{workspace}/skills/{skill_name}/` 目录及其下所有文件 |

**存储说明：** 技能以目录形式存于 `{agent_workspace}/skills/`，由 `skills.Index` 扫描加载。上传技能包解压到该目录，删除技能即删除对应子目录。

### 2.4 工具绑定

| 功能 | 说明 |
|------|------|
| **绑定工具** | 为 Agent 添加一个或多个工具，支持批量绑定 |
| **解绑工具** | 移除 Agent 的某个或全部工具 |
| **绑定关系管理** | 支持查看、调整工具的优先级或执行顺序 |

### 2.5 Agent 增删改查（CRUD）

| 功能 | 说明 |
|------|------|
| **创建** | 新建 Agent，可同时配置工具 |
| **读取** | 按 ID、名称查询；支持分页；可查看绑定关系、技能列表 |
| **更新** | 修改 Agent 配置、提示词、模型、绑定关系 |
| **删除** | 删除 Agent；可选是否同时清理绑定关系及 workspace 下技能 |

## 三、Agent 对话咨询（Agent Chat）

### 3.1 选择 Agent 进行对话

用户可选择已创建的 Agent，与其进行对话咨询。

| 功能 | 说明 |
|------|------|
| **选择 Agent** | 从 Agent 列表中选择目标 Agent，进入对话界面 |
| **发起对话** | 输入问题或指令，发送给所选 Agent |
| **对话咨询** | Agent 基于其配置（模型、提示词、绑定工具、技能）进行回复 |

### 3.2 对话流程

| 步骤 | 说明 |
|------|------|
| **1. 选择 Agent** | 在 Agent 列表或详情页选择要对话的 Agent |
| **2. 进入对话** | 进入该 Agent 的对话界面（会话） |
| **3. 输入消息** | 用户输入问题或指令 |
| **4. Agent 回复** | Agent 调用模型、工具、技能进行推理并回复 |
| **5. 持续对话** | 支持多轮对话，上下文在会话内保持 |

### 3.3 对话能力

| 能力 | 说明 |
|------|------|
| **多轮对话** | 同一会话内保持上下文，支持连续追问 |
| **工具调用** | Agent 可调用已绑定的工具完成用户请求 |
| **技能执行** | Agent 可调用 workspace 中的技能 |
| **会话管理** | 支持新建会话、切换会话、清空会话 |

### 3.4 界面与交互

| 要素 | 说明 |
|------|------|
| **入口** | Agent 列表/详情页提供「对话」入口 |
| **对话界面** | 消息列表 + 输入框，支持发送、流式输出 |
| **会话列表** | 可选：展示当前 Agent 的历史会话，支持切换 |
| **技能管理** | Agent 详情页展示技能列表（来自 workspace/skills 扫描），支持删除技能 |

## 四、通用需求

### 4.1 数据持久化

- 工具、Agent 配置需持久化存储
- 支持导入、导出（如 JSON/YAML）便于备份与迁移

### 4.2 权限与安全

- 支持按用户/角色控制对工具、Agent 的访问
- 脚本执行需在沙箱或受限环境中进行
- 敏感配置（如 API Key）需加密存储

### 4.3 可观测性

- 记录工具、Agent 的调用日志
- 支持执行耗时、成功率等基础统计

## 五、定时任务（Scheduled Tasks）

> 参照 [OpenClaw Cron](https://docs.openclaw.ai/cron) 的定时任务设计，结合本平台 Agent 对话、技能执行能力及**消息渠道（Channel）**设计，定义适合 Portal 的定时任务需求。

### 5.1 概述

定时任务用于在指定时间或按固定间隔自动触发 Agent 执行任务，例如每日摘要、定期数据检查、定时提醒等。执行完成后，可将结果**投递到不同渠道**（见第六章），实现与 Web 会话、Webhook、企业 IM 的联动。

| 能力 | 说明 |
|------|------|
| **调度类型** | 支持 cron 表达式、固定间隔、单次指定时间 |
| **Agent 绑定** | 每个任务绑定一个 Agent，在其 workspace 下执行 |
| **执行方式** | 向 Agent 发送消息触发对话，或直接执行技能脚本 |
| **结果投递** | 与 Channel 对接：执行历史、Webhook、Web 会话 |
| **持久化** | 任务配置与执行历史持久化存储 |
| **可观测** | 记录每次执行状态、耗时、输出摘要 |

### 5.2 任务配置

| 配置项 | 说明 | 必填 |
|--------|------|------|
| 任务名称 | 唯一标识，便于管理 | 是 |
| 关联 Agent | 执行该任务的 Agent ID | 是 |
| 调度类型 | `cron` / `every` / `at` | 是 |
| 调度参数 | 根据类型：cron 表达式 / 间隔秒数 / ISO 时间戳 | 是 |
| 时区 | IANA 时区（如 `Asia/Shanghai`），默认 UTC | 否 |
| 错峰秒数 | 同类型任务随机延迟 0~N 秒执行，避免整点集中；0 表示不错峰 | 否 |
| 执行内容 | 发送给 Agent 的消息内容，或技能执行路径 | 是 |
| 执行模式 | `agent_turn`（对话） / `skill_execute`（直接执行技能） | 是 |
| 超时秒数 | 单次执行超时，默认 300 | 否 |
| 投递配置 | 执行完成后的结果投递方式（见 5.3） | 否 |
| 失败重试 | 失败时重试次数、间隔（如 3 次、间隔 60s） | 否 |
| 启用状态 | 是否启用，支持暂停/恢复 | 是 |

**调度类型说明：**

| 类型 | 参数 | 示例 |
|------|------|------|
| `cron` | 5 字段 cron 表达式 | `0 9 * * *`（每天 9:00） |
| `every` | 间隔秒数 | `3600`（每小时） |
| `at` | ISO 8601 时间戳 | 单次提醒 |

### 5.3 结果投递（与 Channel 对接）

执行完成后，可将结果投递到不同渠道。投递配置作为任务可选配置，与第六章「消息渠道」设计衔接。

| 投递模式 | 说明 | 配置项 |
|----------|------|--------|
| **none** | 仅写入执行历史，不主动推送 | 默认 |
| **webhook** | POST 结果到指定 URL，对接钉钉、飞书、Slack 等 | `delivery.webhook_url`、`delivery.secret`（签名）、`delivery.best_effort`（投递失败不视为任务失败） |
| **session** | 将摘要作为 assistant 消息追加到指定 Web 会话 | `delivery.session_id`；会话须属于同一 Agent |

**Webhook 投递**：请求体为 JSON，包含 `task_id`、`task_name`、`status`、`output_summary`、`error`、`triggered_at`、`finished_at` 等字段；可选 HMAC 签名头。

**Session 投递**：将执行摘要以 Markdown 形式追加到会话消息列表，用户可在 Web 对话界面查看定时任务执行结果。

### 5.4 执行模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **agent_turn** | 向 Agent 发送消息，触发一次完整对话轮次（含工具、技能调用）；每次独立会话，不保留上下文 | 需要 Agent 推理、调用工具或技能的复杂任务 |
| **skill_execute** | 直接执行 Agent workspace 下某技能的脚本 | 简单脚本任务，如数据同步、报表生成 |

### 5.5 任务管理

| 功能 | 说明 |
|------|------|
| **创建** | 新增定时任务，校验 Agent 存在、调度参数合法、投递目标有效 |
| **读取** | 按 ID、Agent、启用状态查询；支持分页 |
| **更新** | 修改任务配置；修改后下次按新调度执行 |
| **删除** | 删除任务；若正在执行可等待完成或取消 |
| **启用/暂停** | 切换启用状态，暂停后不再触发 |
| **立即执行** | 手动触发一次执行（调试或补跑） |

### 5.6 执行历史

| 字段 | 说明 |
|------|------|
| 任务 ID | 关联的定时任务 |
| 触发时间 | 计划触发时间 |
| 实际开始/结束时间 | 执行起止时间 |
| 状态 | `success` / `failed` / `timeout` / `cancelled` |
| 输出摘要 | 执行结果摘要（可截断存储） |
| 错误信息 | 失败时的错误详情 |
| 投递状态 | 若配置了投递，记录 webhook/session 投递是否成功 |

支持按任务 ID、时间范围查询执行历史，便于排查与统计。

### 5.7 与 OpenClaw 的差异

| 维度 | OpenClaw | 本平台（Portal） |
|------|----------|-----------------|
| 执行目标 | main / isolated / session:xxx / current | 绑定 Agent，每次独立会话或直接执行技能 |
| 投递 | announce（频道）、webhook | 执行历史 + 可选 webhook / session 投递，与 Channel 设计衔接 |
| 多通道 | WhatsApp、Telegram、Slack 等 | Web、API、Webhook 渠道；定时任务可投递到 webhook、session |
| 心跳 | 主会话 heartbeat 驱动 | 无 heartbeat，由调度器直接触发 |
| 存储 | 文件 `~/.openclaw/cron/` | 数据库（推荐 MySQL） |

### 5.8 扩展方向（可选）

- **任务依赖**：支持任务链（A 完成后触发 B）
- **条件触发**：除时间外，支持 Webhook 入站触发（与 Channel 的 webhook 渠道联动）
- **投递到 API**：将结果推送到用户配置的 API 端点

## 六、消息渠道（Channels）

> 参照 [OpenClaw Channels](https://docs.openclaw.ai/channels) 与 [Channel Routing](https://docs.openclaw.ai/channels/channel-routing) 的设计，结合本平台以 Web 与 API 为主的架构，定义适合 Portal 的消息渠道需求。

### 6.1 概述

**Channel（渠道）** 表示用户或系统与 Agent 交互的**消息接入与投递入口**。不同渠道有不同的接入方式、认证策略与回复投递逻辑。

| 能力 | 说明 |
|------|------|
| **渠道类型** | Web 对话、API、Webhook 入站等 |
| **路由规则** | 消息来源决定回复投递目标；会话与渠道绑定 |
| **Agent 绑定** | 每个渠道或路由规则可绑定默认 Agent |
| **访问控制** | 按渠道类型配置认证、签名校验、白名单等 |

### 6.2 渠道类型

| 类型 | 说明 | 接入方式 | 回复投递 |
|------|------|----------|----------|
| **web** | Web 对话（内置） | 用户通过 Web 界面选择 Agent、发起会话 | 流式/同步返回至同一会话 |
| **api** | REST / WebSocket API | 程序化调用，请求中指定 `agent_id` | 响应体或 WebSocket 返回 |
| **webhook** | Webhook 入站 | 外部系统 POST 消息到配置的 URL | 可选：同步响应 / 异步回调 URL |

**与 OpenClaw 的差异**：OpenClaw 支持 WhatsApp、Telegram、Discord 等即时通讯平台；本平台以 Web 与 API 为主，Webhook 用于对接企业 IM（钉钉、飞书、Slack 等）或自动化流程。

### 6.3 渠道配置

| 配置项 | 说明 | 必填 |
|--------|------|------|
| 渠道标识 | 唯一 ID，如 `web`、`api`、`webhook:dingtalk` | 是 |
| 渠道类型 | `web` / `api` / `webhook` | 是 |
| 默认 Agent | 未显式指定时使用的 Agent ID | 否 |
| 启用状态 | 是否启用该渠道 | 是 |

**Webhook 渠道额外配置：**

| 配置项 | 说明 | 必填 |
|--------|------|------|
| 回调 URL 路径 | 如 `/webhooks/dingtalk` | 是 |
| 签名校验 | 校验请求签名（如钉钉、飞书、Slack 的签名算法） | 否 |
| 密钥/Token | 用于签名校验或简单 Token 认证 | 否 |
| IP 白名单 | 允许的请求来源 IP 段 | 否 |

### 6.4 路由规则

| 规则 | 说明 |
|------|------|
| **Web** | 会话创建时选定 Agent，整个会话内回复投递至该会话 |
| **API** | 请求体或 Query 中的 `agent_id` 决定 Agent；回复在响应中返回 |
| **Webhook** | 每个 Webhook 配置绑定一个 Agent；回复可同步返回或 POST 到 `reply_url` |

**路由优先级**：显式指定的 `agent_id` > 渠道默认 Agent > 系统默认 Agent。

### 6.5 访问控制

| 渠道 | 认证/校验方式 |
|------|---------------|
| **Web** | 会话级身份（可选登录）；同一会话内上下文隔离 |
| **API** | API Key、Bearer Token；支持按 Key 限流、绑定 Agent |
| **Webhook** | 签名校验（平台特定算法）；IP 白名单；可选 Token |

### 6.6 会话与渠道

| 概念 | 说明 |
|------|------|
| **SessionKey** | 会话标识，用于存储上下文；格式可包含 `agent_id`、`channel`、`peer` 等 |
| **渠道隔离** | 不同渠道的会话相互隔离；同一 Agent 下 Web 会话与 API 调用可分别维护 |
| **回复上下文** | 回复投递至消息来源所在渠道，无需模型选择投递目标 |

### 6.7 扩展方向（可选）

- **企业 IM 插件**：钉钉、飞书、企业微信、Slack 等 Webhook 接入
- **邮件入站**：通过邮件触发 Agent，回复投递至邮件或 Webhook
- **多租户**：按租户/用户隔离渠道配置与会话
- **渠道级模型覆盖**：不同渠道使用不同模型（如 API 用轻量模型、Web 用主力模型）
