# 源码理解：接近 Cursor，并在结构层超过

**日期**: 2026-08-20  
**状态**: 待确认  
**动机**: 同样是 grep / glob / read，Sixath 源码分析仍明显弱于 Cursor（c7aa 找错工作集、c304 跳过 `if errcode == 0`）。工具同类不是能力相同。  
**对照会话**:
- c7aa：代码工具被收窄，读 workspace txt
- c304：`rca_read` 已覆盖整函数，复述时丢掉控制流门
- Cursor 对照：同一套文本工具，但模型、载荷、规划、核对都不同

**已落地（不要重做）**:
- `code` 族 + `AppendCodeAnalysisPrompt`
- Go AST `control_flow` 挂在 `rca_read`（[`framework/tool/go_cfg.go`](../../../framework/tool/go_cfg.go)）
- 终答薄机检：fence 连续原文 + 受控调用必须引用 `when` / 跳过

---

## 0. 决策摘要

| 项 | 选择 |
|---|---|
| 能不能靠「再封装一个 grep」追上 | 不能。差距在五层，工具名只是入口 |
| 接近 Cursor 的必要条件 | **同级代码模型** + **更肥的观察**（上下文行、整函数、CFG 不被压缩掉） |
| 超过 Cursor 的打法 | Cursor 默认也不跑 AST。Sixath 用编译器/AST 当预言机：路径表、入边、场景可达性、机检。判断力可以略弱，结构正确性可以更强 |
| 不做什么 | 自研通用语言无关程序分析平台；用 MEA 任务验收审计器顶替源码核对；把模型差距假装成提示词问题 |

**一句话**：Cursor 赢在模型和阅读习惯；Sixath 要先把「看见什么」做成 Cursor 级，再用 AST/LSP/机检做成 Cursor 没有的硬保证。

---

## 1. 目标与非目标

### 目标

用户用绑定了 `rca_code` / `rca_symbol` 的 Agent 问「根据代码，区域已有用户（1105）会不会写本地映射」时：

1. 工作集是 code roots 里的 `*.go`，不是 workspace txt。
2. 读函数时上下文里同时有原文和 `control_flow` 路径表。
3. 终答点名 `InsertUnionUserAreaInfo` 却不提 `errcode == 0` / 跳过 → 回压，不能发出去。
4. 跨仓入边（谁调用了）是工具结果，不是模型猜。
5. 长会话里 CFG / 关键 `rca_read` 不被 L2 剪成「曾经读过某文件」。

### 非目标

- 用提示词让弱模型「像 Cursor 一样想」
- 一期 Python/Java AST（咪咕主仓是 Go；其它语言后挂同一 `control_flow` JSON）
- 符号执行、跨函数数据流、全仓图数据库（三期可选）
- 改 Web 排版、Gateway、鉴权

### 诚实上限

- **接近 Cursor 的流畅判断**：必须换/叠同级代码模型。工具再好，弱模型仍会在无 CFG 的语言、注释、业务隐喻上输。
- **超过 Cursor 的正确性**：可以。Cursor 读代码默认也是文本，没有强制路径表、没有终答机检、没有多仓 roots 白名单。这些是 Sixath 的主场。

## 2. 五层差距（为什么同样三件套差一截）

```
用户问题
  → 模型（推理）
  → 观察（grep/read 到底返回什么）
  → 导航（下一步读谁：入边/定义/整函数）
  → 上下文（读到的东西下一轮还在不在）
  → 核对（终答能不能和原文/路径表对上）
```

| 层 | Cursor | Sixath 现状 | 差在哪 |
|---|---|---|---|
| 模型 | 强代码模型，内部近似 CFG | 会话模型偏对话/报告 | 读到了仍拼 happy path（c304） |
| 观察 | 整文件 + grep 可带上下文 | `rca_grep` 多单行 snippet；read 可裁窗口 | 模型常拿一行在想 |
| 导航 | 一轮并行多文件；习惯读包围函数 | ReAct 步数少；停在第一击；`rca_symbol` 有但少用 | 入边靠提示，不靠工具 |
| 上下文 | 刚读的源码尽量留着 | L0/L2 会剪工具正文 | 下一轮只记得「读过 helper.go」 |
| 核对 | 引用行号纪律（软） | CFG 机检刚做（硬，仅 Go） | 报告体裁会诱导伪源码 |

工具名相同，**载荷、规划、记忆、核对**都不同。

---

## 3. 分层补什么

每一层只补该层的缺口。不要用提示词同时冒充四层。

### L0 模型 — 接近的必要条件

**补什么**

- 源码分析 Agent（`code` 族激活时）绑定与 Cursor 同级的代码模型；排障/闲聊可保留便宜模型。
- 路由：`FamilyCode` → `model_code`；其余保持现网。

**为什么这样补**

- c304 是复述期走 happy path，不是没工具。弱模型 + 再长的提示仍会拼伪源码。
- 全站换模型贵；只在 code 族换，成本和意图面一致。

**解决什么**

- 「读到了仍讲错」里纯推理那一截。
- 别名、接口、业务隐喻（「区域已有用户」= `errcode==1105`）的对齐。

**不解决**

- 单行 snippet、L2 剪掉 CFG、第一击停工。这些换模型也还会犯，只是少一点。

### L1 观察 — 让工具返回 Cursor 级的「看见」

**补什么**

1. **`rca_grep` 带上下文**：`before`/`after` 默认 3～5 行（对标 `rg -C`）。命中行在 `if` 块内时，模型直接看见门，而不必再赌会不会 `rca_read`。
2. **`rca_read` 默认扩到整函数**（Go 已有 AST）：若窗口落在函数内，`content` 扩到函数 span；另给 `requested_range` 以免误会。CFG 继续挂整函数（已做）。
3. **CFG 保活**：L2 pre-prune 不得把 `control_flow` 打成「已读 helper.go」。实现：工具结果里 `control_flow` 标 `pin` / 单独短消息，或剪 `content` 留路径表。
4. **grep 跳过生成物**：默认排除 `vendor/`、`*_gen.go`、workspace `*.txt` 摘录（code roots 内）。

**为什么这样补**

- Cursor 的优势很大一部分是「第一次检索就看见周围」；Sixath 第一次只给一行，等于逼模型脑补。
- 扩函数比再发明 `rca_cfg` 工具更稳：模型不会漏调。

**解决什么**

- 跳着看的观察侧：门不在 snippet 里。
- c304 类问题的前置：就算模型懒得引用 CFG，原文窗口里也有完整 `if`。

**不解决**

- 跨文件「谁调用了」（那是 L2 导航）。
- 终答改写代码块（那是 L4 核对）。

### L2 导航 — 把 Cursor 的阅读习惯做成工具

**补什么**

1. **`rca_symbol` 当默认入边**：`action=references` 对当前函数/调用，返回仓内调用方列表（gopls 已有）。系统提示改成：定位符号后**必须** `references`，禁止把入口 handler 当唯一源头。
2. **工作集工具（可选，一期可先协议）**：一次返回 `{entry, callees, callers, cfg}`，减少 ReAct 步数浪费。二期再做成 `code_workset`。
3. **并行**：code 族下允许 grep/read/symbol 并行（现网已有并行工具能力则打开；`rca_symbol` 现 `RequiresSequential`，同仓 pool 可串、跨文件 read 应并行）。
4. **停机条件工具化**：入边为空或全在 roots 外 → 允许下结论；否则不准宣称「整体流程」。

**为什么这样补**

- Cursor 看起来懂，是因为它会顺着 import/调用再读三四个文件。Sixath 停在第一击，是规划和步数问题。
- 入边用 LSP 比再 grep 函数名准（同名方法、包装函数）。

**解决什么**

- c7aa 类「第一模块就是全部」。
- 「存档迁移」多仓：union-access / area-servo 不会只讲一个 handler。

**不解决**

- 函数内部的 `if`（那是 CFG）。
- 模型把 1105 当成功码的业务语义（模型和场景求值）。

### L3 上下文 — 读过的结构下一轮还在

**补什么**

1. **Code pin**：本轮 `rca_read.control_flow` + 最后 N 次成功 `rca_read` 的函数 span，L2 摘要时保留结构，不把路径表融进散文。
2. **工作集卡**（短结构化旁路，不进聊天正文）：`files[]`、`functions[]`、`open_questions[]`，每轮更新，压缩后仍注入。
3. **禁止用 MEMORY/txt 顶替 pin 里的源码。**

**为什么这样补**

- 长分析（存档迁移）必然多轮。Cursor 弱在这里时靠再读文件；Sixath 若剪掉工具正文，等于失忆后靠摘要编。
- CFG 很短，留得起；整文件 content 可以剪，路径表不能剪。

**解决什么**

- 「刚才读过 984 行，现在终答当它不存在」。
- 步数够、上下文没了的假中断。

### L4 核对 — 超过 Cursor 的主场

**补什么（在已有薄机检上长）**

1. **已有**：fence 必须是连续原文；点名受控调用必须带 exclusive `when` 或「跳过」。
2. **场景绑定**：用户话里的错误码/分支（`1105`、`已有用户`）若出现在某条 path 的 `when` 的否定侧，终答不得把该 path 上的 `calls` 说成发生。例如 1105 → 命中 `errcode != 0` 路径 → Insert 不可达。这比「必须提到 errcode==0」更贴问题。
3. **入边完备性（软）**：宣称「整体流程 / 唯一源头」时，本轮须有至少一次 `references` 或 caller-grep；否则回压「未扫入边」。
4. **LLM 审计保持 fail-open、不当主路径**（已定）。

**为什么这样补**

- Cursor 没有这层硬闸，靠模型和引用纪律。Sixath 模型更弱，必须机检。
- 场景绑定才能打死 c304 的「散文里不点函数名、只说会写映射表」——若用户问的是 1105，机检可对「写库动词 × 当前路径不可达」。一期若动词难抽，仍要求点名调用；二期加场景×路径。

**解决什么**

- 伪源码、跳 `if`、1105 当会 Insert。
- 「超过 Cursor」：同一段代码，Sixath 可以拒绝错误终答，Cursor 只会尽量写对。

## 4. 分期与依赖

```
P0 已做: code族 / rca_read+CFG / fence+受控调用机检
P1 观察+保活: grep -C / read扩函数 / L2 不剪 control_flow
P2 导航: references 默认入边 / 并行 read / 停机条件
P3 超过: 场景×路径（1105→Insert 不可达）/ 工作集卡
P4 可选: 跨函数 call-graph、多语言 AST 适配同一 JSON
```

| 期 | 做什么 | 依赖 | 可独立验收 |
|---|---|---|---|
| **P0** | CFG + 薄机检 + 提示 | 已实现，需部署 | c304 夹具单测已有 |
| **P1** | grep 上下文；read 扩函数；pin CFG | P0 | 窄窗口 read 的 content 含整函数；L2 后仍见 `when` |
| **P2** | symbol references 协议+可选 workset | P1，gopls 已有 | 「谁调用了 X」工具结果含 caller 路径 |
| **P3** | 场景×路径机检 | P0 CFG | 问 1105 时「会 Insert」必回压，即使不点函数名也可二期做 |
| **P4** | 图/多语言 | P2 | 非 Go 仓不崩溃，fail-open |

P1 不换模型也能明显接近 Cursor 的「看见」。  
P0+P3 是超过 Cursor 的正确性。  
L0 换模型与 P1 可并行，互不阻塞。

## 5. 成功标准

同一 Agent、同一 code roots（如 `D:\workspace\migu`）：

| 题 | 必须 |
|---|---|
| 根据代码分析存档迁移整体流程 | `code` 族；`rca_grep` 在 registry；结论引用 `*.go`；有入边或明示未扫 |
| 区域已有用户 / 1105 会不会写映射 | CFG 显示 Insert 仅 `errcode==0`；终答不得说会 Insert；可保留报告排版 |
| 只问 GitLab | 不激活 code/rca（现网负例仍成立） |
| 窄窗口 rca_read 977-985 | 仍返回整函数 content（P1）+ control_flow（P0） |

回归以单测为主：CFG 夹具、grep `-C`、pin、机检。不强制 LLM 端到端。

## 6. 风险

- **grep `-C` 与扩函数撑爆上下文**：默认 C=3、函数上限（如 400 行），超长函数只返回 CFG + 签名 + 请求窗口。
- **gopls 慢 / sequential**：references 失败则退回 grep 函数名，并在结果里标明 `symbol_ok: false`。
- **场景×路径误伤**：用户没给场景时不要用 1105 规则；只在问题文本匹配到字面量/错误码时启用。
- **换模型成本**：只绑 code 族；评测用 c304/c7aa 黄金会话，不靠体感。

---

## 7. 建议的落地顺序（确认后实施）

1. 部署并打开 P0（CFG + 机检）——已经能打死 c304 主路径（点名 Insert）。
2. P1 观察：这是「接近 Cursor」性价比最高的一步。
3. 并行评估 code 族模型升级。
4. P2 入边工具化 → P3 场景×路径（超过 Cursor 的那一刀）。
